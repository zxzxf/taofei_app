# 聊天界面功能补齐任务计划

> 对标参考界面的功能点，补齐 taofei_app 聊天界面缺失的交互能力。

---

## 一、背景与目标

参考界面（Doubao Seed 风格）在聊天界面提供了以下增强交互：

- 顶部命令输入框（快捷指令入口）
- Agent 执行状态指示器（`Explored N files`、`Editing`）
- 输入区工具栏（语音输入、截图、清除、停止）

当前 taofei_app 的 [ChatView.vue](file:///d:/workspaces/20260904/taofei_app/frontend-vue/src/views/ChatView.vue) 仅具备基础的消息收发、图片上传、模型切换能力，缺少上述交互，用户在 Agent 长任务执行中无法中断、无法直观感知进度。

**目标**：补齐 7 项缺失功能，提升聊天界面的可用性与专业感。

---

| 编号 | 功能 | 优先级 | 复杂度 | 依赖后端 |

## 三、各功能详细设计

### F1：停止按钮（中断当前任务）

**现状**：后端 [main.py#L3771](file:///d:/workspaces/20260904/taofei_app/backend/main.py#L3771) 已有 `POST /api/agent/cancel/{task_id}`，WebSocket 也支持 `cancel_task` 消息，但前端无停止按钮。

**前端改动**（[ChatView.vue](file:///d:/workspaces/20260904/taofei_app/frontend-vue/src/views/ChatView.vue)）：

1. 输入区 `chat-input-row` 内，当 `currentSession.sending === true` 时，将发送按钮替换为停止按钮 `⏹`。
2. 点击停止按钮调用 `stopAgent()`：
   - 通过 WebSocket 发送 `{ type: "cancel_task", task_id }`（优先）。
   - 若 WS 未连接，回退 `fetch('/api/agent/cancel/' + task_id, { method: 'POST' })`。
   - 关闭 SSE 连接 `aiMsg._es?.close()`，取消 WS 订阅 `aiMsg._wsUnsub?.()`。
   - 将 AI 消息置为 `pending: false`，文本显示 `⏹️ 已取消`，`s.sending = false`。

**验收标准**：Agent 执行中点击停止，任务在 2 秒内中断，UI 显示"已取消"，可继续发送下一条消息。

---

### F2："Editing" 编辑状态指示器

**现状**：Agent 调用 `write_file` 时，前端时间线显示命令项，但无独立的"正在编辑"徽章。

**前端改动**：

1. 在 AI 消息气泡头部或时间线上方，增加状态徽章区域。
2. 监听 `timeline` 中 `type === 'command' && name === 'write_file' && status === 'running'` 的项。
3. 当存在运行中的 `write_file` 时，显示带网格图标的 `Editing` 徽章，点击可展开查看正在编辑的文件路径。
4. 可扩展：`read_file` / `list_directory` 运行时显示 `Reading` 徽章。

**验收标准**：Agent 写入文件时，消息区顶部实时出现 `Editing` 徽章，文件写入完成后消失。

---

### F3："Explored N files" 文件探索计数器

**现状**：无文件探索统计。

**后端改动**（[agent_tools.py](file:///d:/workspaces/20260904/taofei_app/backend/agent_tools.py) 或 agent_runner）：

1. 在 Agent 执行上下文中维护 `explored_files: set[str]`。
2. `read_file`、`list_directory`、`grep_code` 执行时，将涉及的文件路径加入集合（去重）。
3. 通过 `task_update` 事件或 `delta` 推送 `explored_count` 字段。

**前端改动**：

1. 在 AI 消息状态区显示 `Explored N files`，N 为去重后的文件数。
2. 数字随工具调用实时递增。

**验收标准**：Agent 读取/搜索文件后，状态区显示已探索的不同文件数量。

---

### F4：顶部命令输入框（快捷指令）

**现状**：仅底部一个输入框。

**前端改动**：

1. 在 `chat-area-head` 下方、`chat-messages` 上方增加一个紧凑的命令输入框。
2. 支持 `/` 触发快捷指令列表（如 `/clear`、`/memory`、`/commit`、`/model`）。
3. 也可作为全局搜索框，输入关键词搜索会话内容（复用现有 `/api/sessions/search`）。
4. 回车执行对应指令或搜索。

**验收标准**：顶部输入框支持 `/` 快捷指令和关键词搜索，不影响底部主输入框。

---

### F5：清除上下文/记忆按钮（橡皮擦）

**现状**：仅顶部有"清空当前"按钮，输入区无快捷清除。

**前端改动**：

1. 输入区工具栏增加橡皮擦图标按钮。
2. 点击弹出确认框，提供两个选项：
   - 清空当前会话消息（复用 `clearCurrent()`）。
   - 清除当前工作空间记忆（调用后端 memory_forget 接口，需新增批量清除 API）。
3. 默认操作：清空当前会话消息。

**验收标准**：点击橡皮擦可快速清空当前会话，无需滚动到顶部。

---

### F6：语音输入（麦克风）

**现状**：无语音输入。

**方案**（二选一）：

- **方案 A（浏览器原生，零成本）**：使用 `webkitSpeechRecognition` API，点击麦克风开始录音，识别结果填入输入框。仅支持 Chrome/Edge。
- **方案 B（后端 ASR）**：录音后上传到后端，调用语音识别 API（如 Whisper / 百度 / 讯飞）转文字。支持多浏览器，需后端接口。

**前端改动**：

1. 输入区增加麦克风按钮。
2. 方案 A：实例化 `webkitSpeechRecognition`，`onresult` 时将识别文本追加到 `inputText`。
3. 录音中按钮高亮，再次点击停止录音。

**验收标准**：点击麦克风说话，文字自动填入输入框，可继续编辑后发送。

---

### F7：截图/裁剪（剪刀）

**现状**：无截图功能。

**方案**：

- 使用 `html2canvas` 截取聊天区域，或调用 Electron 桌面截图 API（[desktop/main.js](file:///d:/workspaces/20260904/taofei_app/desktop/main.js)）。
- 截图后作为图片附件填入输入框（复用 `pendingImages`）。

**前端改动**：

1. 输入区增加剪刀按钮。
2. 点击后弹出截图区域选择（或直接截取当前会话可见区域）。
3. 截图生成 dataURL，push 到 `pendingImages`，显示在输入框上方预览区。

**验收标准**：点击剪刀可截取屏幕/聊天区域，截图自动成为待发送附件。

## 四、实现顺序建议

```
第 1 步：F1 停止按钮（P0，后端已有，纯前端，快速见效）
第 2 步：F5 清除按钮（P2，低复杂度，顺手完成）
第 3 步：F2 Editing 状态（P1，前端为主）
第 4 步：F3 Explored 计数器（P1，需后端配合）
第 5 步：F4 顶部命令框（P1，前端为主）
第 6 步：F6 语音输入（P2，方案 A 优先）
第 7 步：F7 截图功能（P3，视需求优先级）
```

## 五、风险与注意事项

1. **停止按钮**：需确保后端 `cancel_flag_getter` 在 ReAct 循环各阶段都能被检查到，避免无法中断长工具调用。
2. **状态指示器**：`Editing` / `Explored` 的数据来源需统一，避免 WS 和 SSE 两种通道推送格式不一致。
3. **语音输入**：浏览器原生 API 兼容性有限，需做 feature detection，不支持时隐藏按钮。
4. **截图功能**：`html2canvas` 对跨域图片和 iframe 支持有限，Electron 环境下优先用系统截图 API。
5. **UI 一致性**：新增按钮需遵循现有 `chat-input-row` 的布局和主题变量（`var(--accent)` 等）。
