# Taofei App Hermes 能力补齐任务计划（第一梯队）

> 定位：性能层已追平 Hermes（P0-P2 完成：首字 342ms / 前缀缓存 97% / Session 化 /
> 上下文压缩），本计划补齐**能力层**四大核心差距，让 Taofei 从"快"走向"强"。

## 总体目标

| 梯队 | 内容 | 核心收益 | 工期 |
|------|------|---------|------|
| **A** | 联网工具生态（搜索/网页提取/浏览器） | 从"只会本地工具"到"能查资料" | 1 周 |
| **B** | 技能自学习闭环 | 从"静态技能"到"越用越强"（Hermes 灵魂） | 1 周 |
| **C** | 子代理并行（激活 Crew 底层） | 复杂任务拆分并行，多线程效率 | 1 周 |
| **D** | 记忆分层 + 会话全文检索 | 从"记得住"到"懂你 + 搜得到" | 1 周 |
| **合计** | | | **3-4 周**（可 2 人并行到 2 周） |

---

## 任务 A：联网工具生态（1 周 / 4.5 人天）

> 目标：Agent 能搜索、读网页，能力面从本地扩到互联网。

### 选型（先决）

| 方案 | 成本 | 稳定性 | 建议 |
|------|------|--------|------|
| DuckDuckGo HTML 接口（免费无 key） | 0 | 中（可能限流） | ✅ 内置默认 |
| Tavily API（免费 1000 次/月） | key 免费 | 高 | ✅ 可配置增强 |
| Serper / 百度 / Bing API | 付费 | 高 | 用户可选 |

### 子任务表

| 子任务 | 说明 | 预估 | 产出 |
|--------|------|------|------|
| A1 web_search 工具 | DDG 免费实现 + 可选 Tavily key；返回 标题/URL/摘要 | 1d | `backend/tools/web_search.py` |
| A2 web_extract 工具 | httpx 抓取 → HTML→Markdown（html2text 轻依赖），限长截断 | 1d | `backend/tools/web_extract.py` |
| A3 工具注册 | 并入 TOOLS + schema + 流式执行兼容 | 0.5d | agent_tools 扩展 |
| A4 真实浏览器 | Electron 内 BrowserView/CDP 或 Playwright（可选）。**判定：二期**（依赖桌面壳重构，本计划不排期，标注设计） | — | 设计备忘 |
| A5 测试 | 搜索/提取端到端 + 结果截断 + 出错降级 | 1d | 集成测试 |

**验收**：对话中问"查一下 X 的最新进展"→ Agent 自动搜索+读页+总结。

---

## 任务 B：技能自学习闭环（1 周 / 5 人天）

> 目标：Agent 把做过的流程沉淀为可复用技能（Hermes 的 skill_manage 机制）。

### 子任务表

| 子任务 | 说明 | 预估 | 产出 |
|--------|------|------|------|
| B1 技能表升级 | skills.data JSON 增加 version/source/usage_count/updated_at/auto 标记；迁移兼容 | 0.5d | db.py 扩展 |
| B2 create_skill 工具 | Agent 可调用：传入 name/description/步骤内容 → 入库（自动技能） | 1d | 新工具 + 校验 |
| B3 沉淀判定 hook | 任务完成后后台 LLM 判断"该轮是否有可复用流程"→ 生成技能草稿（只读，不自动入库） | 1d | session hook 扩展 |
| B4 技能确认 UI | 消息气泡"沉淀为技能"按钮 + 草稿预览/编辑/入库（用户把关，避免垃圾技能） | 1d | ChatView + SkillsView |
| B5 技能调用统计 | usage_count 累加、失败标记；多次失败提示用户改进/删除 | 0.5d | 工具执行处埋点 |
| B6 技能注入优化 | 自动技能按相关度动态注入（避免全量塞 system 撑爆前缀缓存） | 1d | 技能选择器 |

**验收**：完成一次多步任务 → 出现"沉淀为技能"草稿 → 确认后，新对话命中场景自动注入该技能并生效。

**关键设计约束**：自动技能**必须用户确认才入库**（防脏技能）；技能描述注入保持前缀稳定（不破坏 DeepSeek 缓存）。

## 任务 C：子代理并行（1 周 / 5 人天）

> 目标：复杂任务由单 Agent 串行 → 自主拆分并行（Hermes delegate_task 模式）。

### 先决勘察

taofei_api 导出 Agent/Crew/Task/Process（`_build_crew` 已在 /api/run 用过双 Agent Crew）。
风险点：taofei_api Agent 的 `llm=` 参数是否兼容 `OpenAICompatLLM`（接口是 .call/.model/.stream，
Agent 内部可能要求自有接口或 langchain LLM）→ **C0 验证先行**，不兼容则子代理直接复用
taofei_app 自己的 runner（更可控，推荐）。

### 子任务表

| 子任务 | 说明 | 预估 | 产出 |
|--------|------|------|------|
| C0 taofei_api Crew 对接验证 | OpenAICompatLLM 喂 Agent 冒烟；不兼容则放弃 Crew 走自研 | 0.5d | 验证报告 |
| C1 子任务执行器 | `delegate_tasks(specs)` 工具：每个 spec 独立上下文（消息隔离）+ 独立 runner 线程并行 + 错误隔离 | 2d | `backend/agent/delegator.py` |
| C2 任务分解提示 | 系统提示词引导：任务含多独立子问题时主动拆解调用 delegate | 0.5d | prompts 更新 |
| C3 汇总报告 | 子结果收集 → 一次 LLM 汇总成最终回答（含每子任务来源） | 1d | 汇总逻辑 |
| C4 前端展示 | 子代理并行卡片（N 个子任务同时运行 + 各自结果） | 1d | ChatView |

**验收**：一次问 3 个独立问题（如"对比 3 个框架的现状"）→ 3 个子代理并行执行，总耗时 ≈ 最慢单个而非 3 倍之和。

## 任务 D：记忆分层 + 会话全文检索（1 周 / 4.5 人天）

> 目标：记忆从"单层工作区向量"升级为"用户画像 + 环境事实 + 会话可检索"。

### 子任务表

| 子任务 | 说明 | 预估 | 产出 |
|--------|------|------|------|
| D1 记忆分型 | memory_entries 加 kind 字段（user_profile / workspace_fact / episodic）；现有数据迁 episodic | 0.5d | db.py + memory.py |
| D2 用户画像维护 | 对话后 LLM 提取用户偏好/身份（类似 save_memory 扩展，加 kind=user_profile 分类 + 去重合并） | 1d | memory.py 扩展 |
| D3 画像注入 | 每轮 system 注入 user_profile 摘要（短，≤500 字，前缀稳定） | 0.5d | prompts 组装 |
| D4 会话 FTS5 检索 | session_messages 建 FTS5 虚拟表（同步维护）；API `/api/sessions/search?q=` | 1.5d | db.py + main.py |
| D5 前端历史搜索 | 侧栏搜索框 → 命中会话列表 → 点击打开并定位 | 1d | ChatView |

**验收**：① 跨会话记住用户偏好（如"我习惯中文回答、代码要带注释"）并在新对话生效；
② 输入关键词搜到数月前的对话内容。

## 依赖关系图

```
A (联网工具)  ──┐
                ├──► 无强依赖，四线可并行（文件互不冲突：tools/ 新目录 vs db/memory vs agent/delegator vs ChatView）
B (技能闭环)  ──┤      仅 B/D 同改 db.py/memory.py 需注意合并节奏
C (子代理)    ──┘
D (记忆检索)  ──► C0 若走 Crew 需先验证；走自研 runner 则零依赖
```

## 里程碑排期（1 人串行）

```
第 1 周：A1-A4 + B1-B2（工具 + 技能基建）
第 2 周：B3-B6 + C0-C1（技能闭环 + 子代理核心）
第 3 周：C2-C4 + D1-D4（并行整合 + 记忆/检索）
第 4 周：D5 + 四线联调 + 回归 + 验收
```

## 验收指标

| 指标 | 优化前 | 目标 |
|------|--------|------|
| 联网问答 | ❌ 无法搜索 | ✅ 搜索→读页→总结全自动 |
| 技能沉淀 | 手动写技能 JSON | 一键/自动生成草稿→确认入库→自动注入 |
| 多问题任务耗时 | 串行 N 倍 | 并行后 ≈ 最慢子任务 ×1.2 |
| 用户偏好记忆 | 无 | 新对话自动生效 |
| 历史会话检索 | 无 | 关键词全文命中 <1s |

## 关键风险

| 风险 | 缓解 |
|------|------|
| DDG 免费接口限流/不稳定 | Tavily 可配 key 兜底；工具返回错误可重试提示 |
| 自动技能质量差污染 | 用户确认才入库 + 注入按相关度 + 可一键删除 |
| taofei_api Crew 不兼容自研 LLM | C0 提前验证；不兼容直接自研 delegator（更可控） |
| FTS5 在打包版 SQLite 缺失 | init 时检测，缺失降级 LIKE 检索 |
| 注入技能/画像破坏前缀缓存 | 摘要短、顺序固定、放 system 固定尾部 |
