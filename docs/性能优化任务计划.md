# Taofei App 性能优化任务计划

## 总体目标

| 阶段 | 目标 | 体感提升 | 工期 |
|------|------|---------|------|
| **P0** | 核心体验优化（流式 + FC 默认 + 并行工具） | 速度体感 3-5 倍 | 2 周 |
| **P1** | 架构级优化（Session + 前缀缓存 + 去中间层） | 多轮对话再快 2-3 倍 | 2 周 |
| **P2** | 长对话 + 前端 + 细节优化 | 长对话不减速 + 流畅渲染 | 1 周 |

## P0：核心体验优化（2 周 / 10 人天）

> 目标：FC 默认 + 真正流式 + 并行工具，体感速度从"慢"到"跟 Hermes 差不多快"

| 子任务 | 说明 | 预估工时 | 产出 |
|--------|------|----------|------|
| 1.1 确认 FC runner 功能完整性 | 对比 ReAct 和 FC 的功能差距，列出 FC 缺失的能力 | 0.5d | 差距清单 |

| 1.5 降级检测 | 模型不支持 FC 时自动切回 ReAct，日志记录 | 0.5d | 自动降级逻辑 |

## 慢原因总结

### 十大性能瓶颈（按影响排序）

1. **ReAct 文本解析 vs 原生 Function Calling** — 单轮慢 40-60%
2. **没有 Token 级流式输出** — 体感慢 3-5 倍（等待焦虑）
3. **串行工具调用** — 多工具场景慢 2-4 倍
4. **无前缀缓存 / Prompt Cache** — 多轮对话慢 2-3 倍
5. **Task 式架构 vs Session 式架构** — 每次重建开销 + 无缓存
6. **工具太少，弯路多** — 完成任务多 30-50% 轮次
7. **LangChain 中间层开销** — 单次多 50-150ms
8. **没有上下文压缩** — 长对话越来越慢
9. **SSE 轮询间隔 2 秒** — 额外延迟 0-2s
10. **前端全量替换渲染** — 长内容卡顿明显
